# 技能：健康周报（weekly_report）

## 技能目标

为指定老人生成一份**近 7 天**的健康周报，输出固定四个章节，
每条建议都要标注知识来源，便于家属核对与答辩演示时的"可溯源"要求（FR-09 / AC-13 / AC-14）。

用户本次的原始请求是：

> {{arguments}}

## 执行步骤（按顺序执行，所有数值必须来自工具返回）

### 第 1 步：查询近 7 天体征趋势

对下面 4 个指标分别取近 7 天序列（工具：`get_vitals`，参数 `days=7`）：

| 指标字段 | 中文名 | 关注点 |
| :--- | :--- | :--- |
| `heart_rate` | 心率 | 均值、最高、最低、是否连续走高 |
| `blood_pressure_sys` | 收缩压（高压） | 均值、最高、超过 180 的天数 |
| `blood_pressure_dia` | 舒张压（低压） | 均值、最高、超过 110 的天数 |
| `spo2` | 血氧 | 最低值、低于 90% 的次数 |

对每个指标算出：**均值 / 最大值 / 最小值 / 与上周相比的变化方向**。
数据不足 3 天时，在报告里明确写"数据不足，暂不做趋势判断"，不要用 1~2 个点编趋势。

### 第 2 步：查询这 7 天的告警记录

- 工具：`get_alert_list`（本地/MCP 告警查询；取不到时用 `get_vitals` 的异常点推断）
- 需要聚合：**按天统计条数**、**按级别统计条数**（高危 / 中危 / 低危）、
  列出**最严重的 3 条**（时间 + 类型 + 数值 + 描述）。
- 没有告警时如实写"本周无异常告警"，这是好消息，不要为了凑内容编造。

### 第 3 步：查询用药依从性

- 工具：`get_medication_schedule` 取用药计划，`get_medication_records`（或本地 DAO）取近 7 天记录。
- 计算：`依从率 = 已服条数 / 应服条数 × 100%`
- 同时列出**漏服明细**：药名 + 计划时间 + 状态（待服 / 已服 / 漏服）。
- 依从率 < 80% 时要在建议章节单独给一条提醒。

### 第 4 步：检索知识库给出建议

- 工具：`search_knowledge`（参数 `query` + `top_k=5`，可带 `disease_type`）
- 检索词按第 1 步的异常指标构造，例如"老年 收缩压 偏高 日常管理"。
- 检索失败（Milvus 不可用）时自动走关键词检索；仍失败则写静态建议：
  "请咨询专业医生，紧急情况拨打 120"。

### 第 5 步：按四章节输出周报

标题固定：`# {老人姓名} 健康周报（{起止日期}）`

四个章节**必须齐全、顺序固定**：

```markdown
## 一、指标概览

| 指标 | 7 日均值 | 最高 | 最低 | 趋势 |
| :--- | :--- | :--- | :--- | :--- |
| 心率（次/分） | 78 | 96 | 62 | 平稳 |
| 收缩压（mmHg） | 138 | 162 | 118 | 缓慢上升 ↑ |
| 舒张压（mmHg） | 86 | 98 | 72 | 平稳 |
| 血氧（%） | 97 | 99 | 94 | 平稳 |
| 体温（℃） | 36.5 | 36.8 | 36.2 | 平稳 |
| 血糖（mmol/L） | 6.1 | 7.2 | 5.4 | 平稳 |

一句话总结：{本周整体评价，必须中性、不诊断}

## 二、异常与告警汇总

- 本周告警共 {N} 条：高危 {a} 条 / 中危 {b} 条 / 低危 {c} 条。
- 最需要关注的三条：
  1. {日期 时间} {类型} {数值} —— {描述}
  2. ……
- 按天分布：{日期:条数, ...}
- 处置情况：{已确认 x 条 / 待确认 y 条}

## 三、用药依从性

- 本周依从率：**{xx}%**（已服 {m} 次 / 应服 {n} 次）
- 漏服明细：
  | 药名 | 计划时间 | 状态 |
  | :--- | :--- | :--- |
  | {药名} | {时间} | {已服/漏服/待服} |
- 提醒：{依从率偏低 / 按时服药，做得很好}

## 四、个性化建议

{针对本周异常指标 + 慢病史，给出 3~5 条可执行建议，每条都带来源标注}

- 建议 1：……（依据：《{文档标题}》{版本} 第 {页码} 页）
- 建议 2：……（依据：{来源}，{版本}，第 {页码} 页）
- 建议 3：……（依据：{来源}，{版本}，第 {页码} 页）

---
> 数据来源：InfluxDB `vital_signs`（近 7 天，10 分钟粒度）+ MySQL `alert_record` / `medication_record`。
> 本报告仅提供健康提示，不构成医疗诊断；如有明显不适请及时就医，紧急情况拨打 120。
```

**溯源硬性要求**：第四章每条建议后面必须紧跟 `（依据：《来源》版本 第 X 页）`，
来源信息取自第 4 步检索结果的 `source` / `version` / `page` 字段
（AC-14：检索结果每条都带 source、version、page，可回溯到原文段落）。

## 禁止事项

1. 禁止编造指标数值、告警条数和页码——没有数据就写"数据缺失"。
2. 禁止出现"确诊""患有严重疾病"等诊断性表述，统一用"指标偏高/趋势需要关注"。
3. 禁止省略四个章节中的任何一个（AC-13 会逐节检查）。
4. 禁止给出具体处方和药量调整（改药量必须由医生决定）。
