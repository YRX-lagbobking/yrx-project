# 本机运行部署指南（混合模式：本机三个库 + Docker 只放 Milvus/InfluxDB）

> 场景：**MySQL / PostgreSQL / Redis 装在本机**，只把 Milvus 与 InfluxDB 放 Docker，
> 后端（FastAPI）、MCP Server、Celery 直接在 Windows 上跑，**不用把应用容器化**。
>
> 对应需求文档 NFR-05（部署）与 R-04（Milvus 内存风险）。

---

## 一、先搞清楚：项目里哪些算"中间件"

中间件 = **独立于业务代码、需要单独安装/启动、进程之间通过网络协议交互的基础服务**。

### 1.1 本项目的 5 个中间件

| 中间件 | 版本 | 端口 | 存什么 | 本指南放哪 | 没有它会怎样（降级行为） |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **MySQL** | 8.0 | 3306 | 用户、健康档案、家属绑定、用药计划/记录、告警记录、知识文档 | **本机** | 服务起不来（核心业务库，无降级） |
| **PostgreSQL** | 16 | 5432 | L2 摘要记忆 `conversation_summary`、LangGraph Checkpointer 表 | **本机** | Checkpointer 自动降级 `InMemorySaver`（重启丢会话）；摘要记忆降级内存字典 |
| **Redis** | 7 | 6379 | L1 窗口记忆、L4 用户画像、会话归属、分布式锁、Celery broker/backend | **本机** | 记忆降级进程内字典、会话校验跳过、Celery 通知落本地队列 |
| **InfluxDB** | 3 Core | 8181 | 生命体征时序 `vital_signs`（心率/血压/血氧/体温/血糖/睡眠） | **Docker** | 检测无数据可查；`is_available()=False`，启动补历史被跳过 |
| **Milvus** | 2.4 | 19530（+9091） | `health_knowledge` 知识向量、`long_memory` 长期记忆向量 | **Docker** | RAG 降级关键词检索；L3 长期记忆降级 ChromaDB/内存 |

### 1.2 还有 2 个"被 Milvus 依赖的基础组件"

Milvus standalone **不是单个容器**，它必须有元数据存储和对象存储，所以会连带起来：

| 组件 | 镜像 | 作用 | 端口 |
| :--- | :--- | :--- | :--- |
| **etcd** | `quay.io/coreos/etcd:v3.5.5` | Milvus 元数据（集合/索引/分区） | 只在容器网络内 2379 |
| **MinIO** | `minio/minio:RELEASE.2023-03-20...` | Milvus 对象存储（向量数据落这里） | 控制台 9001；内部 API 9000 不对外 |

### 1.3 这些**不是**中间件（别搞混）

| 名称 | 真实身份 |
| :--- | :--- |
| `mcp-server`（端口 9000） | **应用服务**，是我们自己写的 MCP 工具服务（FastMCP），不是中间件 |
| Celery | **任务队列框架**（Python 库）；它的 broker/backend 用的是 Redis 这个中间件 |
| Vosk / EdgeTTS | **Python 库**（本地语音识别 / 在线语音合成），没有独立服务进程 |
| APScheduler | Python 库，项目里用 Celery Beat 代替 |
| Nginx | 项目里预留，当前未使用（生产反向代理用） |

## 二、三种运行模式对比（选一种，别混用）

| 模式 | MySQL/PG/Redis | Milvus/InfluxDB | 应用 | 命令 | 适合 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **① 全本机** | 本机 | 本机（需自己装 Milvus，不推荐） | 本机 | 见第三节 | 机器放不下 Docker |
| **② 混合（本指南，推荐）** | 本机 | **Docker** | 本机 | `docker compose -f docker-compose.middleware.yml up -d` | 你现在的诉求 |
| **③ 全容器** | Docker | Docker | Docker | `docker compose up -d` | 答辩/交付演示 |

> ⚠️ **模式②下绝对不要执行 `docker compose up -d`**（那会同时拉起 MySQL/PG/Redis/App，
> 抢占 3306 / 5432 / 6379 / 8000 / 9000，和你的本机服务直接冲突）。

## 三、混合模式：逐步操作（Windows）

### 步骤 0：把原来占端口的容器停掉

如果之前已经跑过全容器模式，先把抢端口的容器停掉（**数据卷保留，不会丢数据**）：

```powershell
cd E:\daimaxiangmu\workspace2\agent_project
docker compose down                 # 停掉并删除容器，保留数据卷
docker ps --format "{{.Names}}\t{{.Ports}}"   # 确认 3306/5432/6379/8181/8000 没有容器占用
```

如果你有手动创建的 InfluxDB 容器（占 8181）：

```powershell
docker ps -a | Select-String influxdb
# 二选一：
#   A) 交给 compose 管理（数据卷 influxdb3_data 同名，历史数据沿用）
docker rm -f influxdb3-core
#   B) 保留它 → 打开 docker-compose.middleware.yml，把 influxdb 整段注释掉
```

### 步骤 1：确认本机三个中间件在跑

```powershell
# 看服务（服务名可能因安装方式不同，用通配符找）
Get-Service *mysql*, *postgres*, *redis* | Select-Object Name, Status

# 起服务（示例，按实际服务名替换）
net start mysql80
net start postgresql-x64-16
# Redis：Windows 原生版/Memurai 一般不注册服务，直接跑
#   redis-server.exe redis.windows.conf
#   或用 WSL：wsl -d Ubuntu redis-server /etc/redis/redis.conf

# 端口验证（有 LISTENING 才算在跑）
Test-NetConnection 127.0.0.1 -Port 3306 | Select-Object TcpTestSucceeded
Test-NetConnection 127.0.0.1 -Port 5432 | Select-Object TcpTestSucceeded
Test-NetConnection 127.0.0.1 -Port 6379 | Select-Object TcpTestSucceeded
```

> 本机没有 Redis 又想省事？也可以把 Redis 留在 Docker（`redis:7-alpine` 单容器，
> 内存占用很小），只是端口 6379 由容器提供，配置不用改。

### 步骤 2：初始化 MySQL（业务库）

```powershell
cd E:\daimaxiangmu\workspace2\agent_project
mysql -uroot -p1234 < sql/init.sql
# 脚本会 CREATE DATABASE health_butler（若不存在）+ 8 张表 + 演示数据
mysql -uroot -p1234 -e "use health_butler; show tables; select user_id,user_name,role from `user`;"
```

### 步骤 3：初始化 PostgreSQL（摘要记忆）

```powershell
psql -U postgres -h 127.0.0.1 -p 5432 -d postgres -f sql/init_postgres.sql
# 验证
psql -U postgres -h 127.0.0.1 -p 5432 -d postgres -c "\d conversation_summary"
```

> **可以跳过这一步**：程序在首次读写摘要记忆前会自动执行
> `CREATE TABLE IF NOT EXISTS conversation_summary (...)`（自愈建表）。
> LangGraph 的 Checkpointer 表也由启动时的 `AsyncPostgresSaver.setup()` 自动创建。

### 步骤 4：Docker 只起 Milvus + InfluxDB

```powershell
cd E:\daimaxiangmu\workspace2\agent_project
docker compose -f docker-compose.middleware.yml up -d
docker compose -f docker-compose.middleware.yml ps      # etcd/minio/milvus 应为 healthy
docker compose -f docker-compose.middleware.yml logs -f milvus
```

**Milvus 首次启动较慢**（start_period 90 秒），看到类似
`Milvus Standalone ... start successfully` 才算就绪。内存不够会让它反复重启：
Docker Desktop → Settings → Resources 把内存调到 **≥ 6~8G**。

验证 Milvus：

```powershell
curl http://localhost:9091/healthz          # 返回 OK
python -c "from pymilvus import connections, utility; connections.connect(host='localhost', port='19530'); print(utility.list_collections())"
# 未灌知识库时输出 []，灌完后输出 ['health_knowledge']
```

建立 InfluxDB 数据库（**只需一次**）：

```powershell
docker exec -it health-influxdb influxdb3 create database --retention-period 30d --token <你的 INFLUX_TOKEN> agent_db
```

### 步骤 5：检查 `.env`（混合模式下的关键 6 项）

```ini
DB_HOST=localhost          # 本机 MySQL
PG_HOST=127.0.0.1          # 本机 PostgreSQL
REDIS_HOST=localhost       # 本机 Redis
INFLUX_URL=http://localhost:8181     # Docker 里的 InfluxDB（端口已映射到本机）
MILVUS_HOST=localhost      # Docker 里的 Milvus（端口已映射到本机）
MCP_SERVER_URL=http://localhost:9000 # MCP Server 跑在本机
RAG_MODE=milvus            # 暂不部署 Milvus 时改成 keyword
```
> 这些值就是仓库里 `.env` 的现状，**不用改**。注意：容器内的应用才需要把 `localhost`
> 换成服务名，而我们是本机跑应用，所以一律用 `localhost`。

### 步骤 6：启动本机三个进程（各自一个终端）

```powershell
cd E:\daimaxiangmu\workspace2\agent_project
python -m venv .venv; .\.venv\Scripts\Activate.ps1; pip install -r requirements.txt

# 终端 1：MCP 工具服务（端口 9000）
python -m mcp_server.mcp_health_server

# 终端 2：后端 + 前端页面（端口 8000）
python -m app.main

# 终端 3：Celery Worker（异步告警通知，Windows 必须 -P solo）
celery -A app.core.celery_app worker -l info -P solo

# 终端 4：Celery Beat（每 DETECT_INTERVAL_MINUTES 分钟自动巡检预警）
celery -A app.core.celery_app beat -l info
```

访问 <http://localhost:8000>（`admin / admin123456`；老人 `u001 / 123456`）。

### 步骤 7：把知识文档灌进 Milvus（RAG 知识库）

```powershell
# 前提：.env 里 DASHSCOPE_API_KEY 已填、RAG_MODE=milvus
python -c "from app.ai.tool.rag_tool import build_knowledge_base; print('入库片段数:', build_knowledge_base('knowledge_docs'))"
```
集合与 HNSW 索引（COSINE / M=16 / efConstruction=200）由程序自动创建，
**不需要手工 `create_collection`**；向量维度从实际 embedding 探测，不会对不上。

### 步骤 8：验收清单

| 检查 | 命令/方式 | 期望 |
| :--- | :--- | :--- |
| 六项依赖探测 | 浏览器打开 `/health` | `{"status":"healthy","mode":"full","detail":{...全 true...}}` |
| MySQL | `mysql -uroot -p1234 -e "use health_butler; select count(*) from medication"` | 有数据 |
| PostgreSQL | `psql ... -c "select count(*) from conversation_summary"` | 表存在（可为 0 行） |
| Redis | `redis-cli keys "window_memory:*"` | 聊过天后能看到键 |
| InfluxDB | `python -m app.test.test_influx` | 写入/查询成功，或打印降级提示 |
| Milvus | `python -m app.test.test_rag` | 切分/入库/检索通过，`list_collections` 出现 `health_knowledge` |
| 三层检测 | `python -m app.test.test_detect` | AC-08 高危命中、AC-10 手动检测不写库 |
| 语音 | 聊天页点"开启语音" | 连续多句识别，随时可停 |

## 五、常见问题

### 1. 摘要记忆写了但读不到 / 日志报 `relation "conversation_summary" does not exist`
说明 PostgreSQL 里没建表。执行 `sql/init_postgres.sql`，或直接重启后端（新版代码会自动建表）。
确认连接串：`.env` 的 `PG_HOST/PG_PORT/PG_USER/PG_PASSWORD/PG_DB` 与 `POSTGRESQL_URL` 要一致。

### 2. Milvus 一直重启 / `docker compose ps` 显示 unhealthy
内存不足（最常见）或 etcd/minio 未就绪。依次检查：Docker Desktop 内存 ≥ 6~8G →
`docker compose -f docker-compose.middleware.yml logs etcd minio` → 再 `logs milvus`。
实在跑不动就 `.env` 设 `RAG_MODE=keyword`，项目照常运行（关键词检索 + ChromaDB 长期记忆）。

### 3. `docker compose up -d` 报端口被占用（3306/5432/6379）
你正在用混合模式却执行了全容器命令。改成
`docker compose -f docker-compose.middleware.yml up -d`。

### 4. Redis 设了密码连不上
`.env` 里补 `REDIS_PASSWORD=你的密码`（代码会自动带上），或把 `REDIS_URL` 写成
`redis://:密码@localhost:6379/0`。

### 5. Celery 起不来 / 卡在 "worker ready" 之后无输出
Windows 必须加 `-P solo`。Redis 既是 broker 也是 backend：broker 连不上时 `notify_family_async`
会抛异常（调用它的节点已做兜底）；另外记住「投递成功 ≠ 已发送」，要确认 Worker 在消费。

### 6. 必须从项目根目录启动
`app/main.py` 里静态目录是相对路径 `./app/html`，`rag_tool` 默认知识库目录是
`./knowledge_docs`。所以命令必须在 `E:\daimaxiangmu\workspace2\agent_project` 下执行。
