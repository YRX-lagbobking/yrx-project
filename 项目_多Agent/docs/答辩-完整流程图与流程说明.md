## 图 2　一次文本对话（端到端，SSE）

```mermaid
sequenceDiagram
    participant B as 浏览器 chat.html
    participant R as chat_router
    participant A as HealthGraphAgent
    participant S as SessionManager 四层记忆
    participant G as 多智能体图
    participant P as Redis / PG

    B->>R: GET /chat?question&session_id&token (EventSource)
    R->>R: JWT 鉴权 + 会话归属校验(403)
    R->>A: health_agent.chat(question, user_id, session_id)
    A->>P: 会话锁 SET NX PX + Lua
    A->>S: 并行读 L1窗口/L2摘要/L3长期/L4画像
    S-->>A: 记忆提示词 dict
    A->>G: astream(input, stream_mode="custom")
    G->>G: planner→manager→workers→summarize
    G-->>A: writer() 逐段文本
    A-->>R: async yield 片段
    R-->>B: data:{"data":"片段","done":false}
    B->>B: botMsg.content += 片段（打字机）
    G-->>A: 结束
    R-->>B: data:{"data":"","done":true}
    A->>P: 写 L1 窗口记忆 + chat_message(PG)
    A->>S: MemoryManager.update(L2/L3/L4)
    B->>B: 关 SSE + 刷新历史 + TTS 播报
```

**要点**：`stream_mode="custom"` 只推 `chat/report/summarize` 三个节点主动 `writer()` 的内容；其它 7 个节点对前端静默。

```mermaid
    MG -->|notify| NF["notify<br/>写告警 + 双通道通知"]
    MG -->|emotion/chat| CT["chat<br/>闲聊/共情 + 家属留言工具 + Skill"]

    RG --> MG
    RK --> MG
    RM --> MG
    RP --> MG
    NF --> MG
    CT --> MG
    MG -->|队列空 且 队列仅 chat| END1([END])
    MG -->|队列空 且 有其它任务| SUM["summarize<br/>汇总成口语化回答"]
    MG -->|任务失败 status=error| RT["retry_count+1 重试同一节点"]
    RT -->|超过 3 次| CT
    SUM --> END2([END])
```

**关键设计（答辩常问）**
| 问题 | 答案 |
|---|---|
| 谁是调度者？ | `manager_node`（纯代码路由，读 `task_queue`），不用 LLM → 可解释、可控、零 token |
| worker 之间怎么通信？ | 共享 `HealthState`（黑板模式），每条 worker 出边回 manager |
| 失败怎么处理？ | 节点写 `status="error"` → manager 重试 ≤3 次 → 超限**降级到 chat**（澄清话术） |
| 为什么只有 manager 用 Command(goto)？ | 统一收口，便于重试/降级/审计；其它节点用静态边回 manager |

## 图 4　定时巡检与告警通知（Celery，**你现在跑的这条**）

```mermaid
sequenceDiagram
    participant BE as Celery Beat 每分钟
    participant RD as Redis broker
    participant W as Celery Worker
    participant IX as InfluxDB
    participant DB as MySQL alert_record
    participant M as SMTP 邮件

    BE->>RD: 投递 auto_detect_all
    RD->>W: 取出任务（必须已注册，否则 NotRegistered）
    loop 每个 role='elder' 用户
        W->>IX: 查询最新/近 7 天体征
        W->>W: detect_anomaly 三层检测
        alt 有异常
            W->>DB: AlertDAO.save(source="auto")
            W->>RD: 投递 notify_family（再一个 Celery 任务）
            RD->>W: 取出 notify_family
            W->>W: 解析家属邮箱（紧急联系人→绑定家属→EMAIL_TO）
            W->>M: send_email（真实 SMTP）
            W->>DB: update_notify_result 回写
        else 无异常
            W->>W: 记录 0 条告警
        end
    end
    Note over W: 发送失败 → self.retry(countdown=60) 最多 3 次
```

**三层检测**（`detect_anomaly`）
| 层 | 判据 | 等级 | 依赖 |
|---|---|---|---|
| 规则层 | 与 `.env` 阈值比较（HR>120、SBP>180、SpO₂<90…） | **高危** | 只要"最新一条" |
| 趋势层 | 当前值偏离 7 天基线 >30% | 中危 | 需要多天历史 |
| 离群层 | 个体 MAD >3 倍 / STD >2 倍 | 中危 | 需要 ≥5 个点 |

## 表 A　图状态关键字段（`HealthState`）

| 字段 | 作用 | 通道语义 |
|---|---|---|
| `messages` | 对话消息 | `operator.add`（累加） |
| `user_id` / `session_id` / `role` | 身份 | LastValue |
| `task_queue` / `current_task` | 任务队列与当前任务（参数载体） | LastValue |
| `task_results` | 各 worker 结果（`status`/`error`…） | 自定义 merge reducer + `{"__reset__":True}` 清空 |
| `retry_count` | 当前任务重试次数（>3 降级 chat） | LastValue |
| `vitals` / `knowledge` / `risk_level` / `risk_reasons` / `anomalies` | 数据与检测结果 | LastValue |
| `notify_channel` / `notify_result` / `need_human_confirm` | 通知留痕 | LastValue |
| `report_type` / `report_content` / `report_path` | 报告产物 | LastValue |
| `final_answer` / `health_step` | 最终回答 / 步骤标记 | LastValue |

> `health_step` 只写不读（不是路由游标）；真正的游标是 `task_queue` + `manager`。

## 表 D　已知缺口 / 改进项（面试官爱问"不足在哪"，这样答很加分）

| # | 现状 | 影响 | 改进 |
|---|---|---|---|
| 1 | 定时巡检路径**不推老人端**（只有对话路径推 WS） | 定时发现异常时老人端不弹窗 | 照抄 `auto_detect_once` 的 WS 通道（~5 行） |
| 2 | 家属端 `family.html` 是**拉取式**（无 WS/轮询） | 家属要手动刷新 | 加 `setInterval(loadAlerts, 30000)` |
| 3 | `/ws/notify` **无 token 校验**（只按 `?user_id=`） | 可冒名订阅告警 | 校验 query 里的 JWT，失败 `close(1008)` |
| 4 | 人工确认后**不补发**（`/alert/{id}/confirm` 只改状态） | 人工确认不闭环 | confirm 后触发发送 |
| 5 | 短信通道已删除；MCP 的 `send_sms` 函数仍保留但不再调用 | — | 或彻底清理白名单/文档 |
| 6 | 关闭了启动补历史（`VITALS_BACKFILL_DAYS=0`） | 趋势/离群层短期缺历史窗口 | 临时改回 1 天（约 5~10 秒启动） |
| 7 | logger 只输出控制台、无文件日志 | 排查困难（如 NotRegistered 只能在窗口看到） | 加 `RotatingFileHandler` |
| 8 | 会话状态在单进程内存（`ws_manager`） | 多副本时推送失效 | Redis pub/sub 广播 |

## 图 10　JWT 登录与请求鉴权（时序图）

```mermaid
sequenceDiagram
    participant B as 浏览器
    participant U as user_router
    participant S as security.py
    participant DB as MySQL user 表
    participant API as 业务接口(chat/alert/report)

    B->>U: POST /user/login {user_name, password}
    U->>DB: UserDAO.verify_login
    DB-->>U: user_id + role（校验 sha256(盐+明文)，compare_digest 防时序攻击）
    U->>S: create_access_token(user_id, role)
    S-->>U: JWT(HS256, payload=user_id/role/iat/exp, 24h)
    U-->>B: {token, user_id, role}（前端存 sessionStorage）

    Note over B,API: 之后每个请求携带凭证（三选一）
    B->>API: Header Authorization: Bearer token
    B->>API: 或 ?token=xxx（专为 SSE/EventSource，浏览器不能设 header）
    B->>API: 或裸 token
    API->>S: Depends(get_current_user) → extract_bearer_token
    S->>S: decode_access_token（验签 + 校验 exp，PyJWT 优先/标准库 HMAC 兜底）
    alt 校验通过
        S-->>API: TokenData(user_id, role)
        API->>API: can_access_user 做数据权限（admin/elder/family）
        API-->>B: 200 业务数据
    else 校验失败
        S-->>B: 401 未认证或登录已过期
    end
```

## 表 E　端点鉴权挂载实况（实测）

| 路由 | 端点数 | 已挂 `get_current_user` | 说明 |
